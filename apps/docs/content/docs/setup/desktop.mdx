The desktop app is a GPUI application written in Rust. It talks to the Kloucy API and starts agents on your machine.

## Build

```bash
cd apps/desktop
cargo build --release
```

The binary lands at `apps/desktop/target/release/kloucy-desktop`.

## Run

```bash
KLOUCY_API_URL=http://localhost:4040 ./target/release/kloucy-desktop
```

<Callout type="warn" title="API URL">
`KLOUCY_API_URL` defaults to `http://localhost:3001`. If your API listens elsewhere (the local setup uses `4040`), set it explicitly, or change it from the **API offline** screen the app shows when nothing answers: the URL is remembered in `~/.config/kloucy/desktop.json`, so the next start does not need the variable again.
</Callout>

## Agents

There is no registry to fill in. Kloucy looks for agent CLIs on your `PATH` (`claude`, `codex`, `opencode`, and others) and offers them in the composer, with the models each one reports. The first message that runs one stores the agent record, so sessions and reviews fill themselves as you work. A CLI needs a one-shot command to answer (`codex exec`, `claude -p`, `opencode run`); Kloucy picks that form by default.

## Sign in

Use the same account as the web app. Create it once through the API or the web sign-up screen, then sign in from the desktop.

## What you get

- **The sidebar is the work**: **New thread** sits at the top, then every project with its threads. A project's chevron folds its threads and its name starts a new thread in that project; a thread opens where it ran, and a small dot shows when its latest run is working, waiting or failed. The `…` menu **settles**, **pins**, **snoozes** (one hour or one day) or **archives** a thread: pinned threads move to **Pinned**, settled ones to **Settled (n)**, whose header folds them away, snoozed ones to **Snoozed (n)**, and archived ones to **Archived (n)**, folded by default, where **Unarchive thread** brings one back.
- **Each thread gets its own checkout**: in a git project, **New worktree** (the default) creates a `kloucy/<thread>` branch and a worktree under `~/.local/share/kloucy/worktrees/`. **Current checkout** runs in the project itself, and the choice is remembered per project. **From …** picks the branch the worktree starts from. A project that is not a git repository runs in place.
- **The thread** is the composer plus the conversation: enter sends, shift+enter adds a line, and every turn after the first resumes the agent's own session so the context survives. What you type is kept per thread, so switching away and back restores the draft. A reply keeps its **Tool calls** (the commands, edits, MCP tools and searches the agent reported), its collapsed **Thought process**, **Copy**, **Retry** and the reason it failed. The picker keeps the installed CLIs, each agent's models, the reasoning levels, favourites and fast mode.
- **Surfaces sit beside the conversation**: **Files** lists the checkout and opens a file with syntax colour, and **Copy path** puts its path on the clipboard; **Diff** shows the change against `HEAD` plus untracked files as additions; **Terminal** runs `$SHELL` in the thread's checkout with its colours, keys and scrollback (`shift-pageup` / `shift-pagedown`), and resizes with the panel; **Agents** lists the thread's runs, newest first; **Browser** opens a URL in your own browser, because GPUI has no embedded webview; **Device** finds Android emulators and running devices, starts an AVD headless and shows a still of its screen when the SDK's `adb` and emulator are installed (the screen is read-only; taps are not forwarded). The panel belongs to the thread and closes with it, and the palette can open any surface without the header.
- **Actions are project commands**: save or edit a name, a shell command and an optional preview URL in **Actions**; the thread header lists them and **Run** executes one in the thread's terminal and fills the Browser with the preview. **Open preview automatically** also opens the URL. An action can also **run on worktree creation**; with **Wait before the agent starts** the first agent run waits for it, and a failure stops the run before the agent starts. Actions are stored per project in `desktop.json`.
- **The loop closes in the thread**: **Commit** stages and commits the worktree with a message, **Push** sets the upstream, **Create PR** pushes and opens a GitHub pull request titled with the thread, and **View PR** opens it. The header shows the same **Create PR** / **View PR** action, and the checkout row shows `+added −removed` for the current change. **Open** launches the checkout in Zed, Cursor, VS Code, VSCodium or the file manager. A failure is a sentence in the bar, not a silent no-op.
- **Search is the palette**: `cmd-k`, or `ctrl-k` away from macOS, finds conversations by title and commands by name. **Enter** opens the first result and **Escape** closes the palette. **Chats**, **Workspaces**, **Inbox**, **Sessions**, **Reviews**, **Decisions**, **Readiness**, **Weekly review**, **Pairing** and **Settings** are still there as palette commands.
- **Chats** lists the conversations this machine remembers, with how many turns each has and where it ran; **Open** brings one back, **Rename** names it, and **Forget** drops it from the list without touching its sessions. Home reopens the last conversation when the app starts.
- **Workspaces** create a workspace and record its intake: project type, package manager, runtime, safe commands, ignored paths, safety mode and whether mobile may supervise it. **Detect project** reads the workspace directory names and fills the profile in, suggesting safe commands and ignored paths for that ecosystem.
- **Inbox** captures tasks with their prompt and state; **Start session** runs one and opens it in Home, and a task that already ran shows **Open run**. **Sessions** lists every run, streams its logs and opens it in Home. A guarded workspace refuses a command that is not in its safe commands.
- **Reviews** lists the files a run changed, approves or rejects them with a reason, records follow-up conditions and opens the run behind them. **Readiness** scores whether the workspace can run agents, with a coloured verdict and the blockers it still has. **Weekly review** summarizes what shipped, what is blocked, what was rejected, risky patterns and next actions, and **Generate review** saves a new one.
- **Pairing** shows a QR code and the `kloucy://pair?token=…` link the code carries; **Copy link** puts it on the clipboard for a phone that cannot scan, and the state (pending, claimed, revoked) is coloured.
- **Settings** shows the API the app is talking to, corrects workspace data, sets the default agent and archives a workspace.

## Command palette

Press `cmd-k`, or `ctrl-k` away from macOS, to open the palette from anywhere in the app. Type to filter; conversations appear under **Threads** and commands below them:

- open a conversation by title
- open a thread surface: **Files**, **Diff**, **Terminal**, **Agents**, **Browser** or **Device**
- copy the checkout path, open the checkout in an editor, or view its pull request
- jump to any supervision section, chats included, or open **Actions**
- start a new workspace
- create a new pairing code

Press **Enter** to open the first result, escape or the shortcut again to close it, or click a row.
