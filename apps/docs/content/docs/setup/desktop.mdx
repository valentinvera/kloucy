The desktop app is a GPUI application written in Rust. It talks to the Kloucy API and starts agents on your machine.

## Build

```bash
cd apps/desktop
cargo build --release
```

The binary lands at `apps/desktop/target/release/kloucy-desktop`.

## Run

```bash
KLOUCY_API_URL=http://localhost:4040 ./target/release/kloucy-desktop
```

<Callout type="warn" title="API URL">
`KLOUCY_API_URL` defaults to `http://localhost:3001`. If your API listens elsewhere (the local setup uses `4040`), set it explicitly, or change it from the **API offline** screen the app shows when nothing answers: the URL is remembered in `~/.config/kloucy/desktop.json`, so the next start does not need the variable again.
</Callout>

## Agents

There is no registry to fill in. Kloucy looks for agent CLIs on your `PATH` (`claude`, `codex`, `opencode`, and others) and offers them in the composer, with the models each one reports. The first message that runs one stores the agent record, so sessions and reviews fill themselves as you work. A CLI needs a one-shot command to answer (`codex exec`, `claude -p`, `opencode run`); Kloucy picks that form by default.

## Sign in

Use the same account as the web app. Create it once through the API or the web sign-up screen, then sign in from the desktop.

## What you get

- **Home** is the composer: write what you want done (it wraps and grows; enter sends, shift+enter starts a new line), pick the agent that should run it, and it starts. The answer appears as a reply in the thread, its fenced code is syntax-coloured, and the composer stays at the bottom for the next message. Each message is a turn, and every turn after the first resumes the agent's own session, so the conversation keeps its context.
- **The picker** (the pill at the composer's bottom right) opens a card with a square per installed agent, a model search, the agent's models with a star for the ones you keep, the reasoning levels that model accepts, and fast mode where the CLI has one. The first nine rows answer to `ctrl-1` … `ctrl-9` (`cmd` on macOS). Your choice is remembered for the next start.
- **A reply carries its context**: a collapsed **Thought process** when the agent reasoned, **Copy** and **Retry** under an answer, a **Changes detected · review** link when the run changed files, and the reason the run failed when it did.
- **The checkout chip** chooses the project to work in, or **No project**, which runs in Kloucy's own git space under `~/.local/share/kloucy/chats` so a message never needs a repository. The row also shows that checkout's git branch, and the chips switch workspace and account.
- **Chats** lists the conversations this machine remembers, with how many turns each has and where it ran; **Open** brings one back, **Rename** names it, and **Forget** drops it from the list without touching its sessions. **New chat** (`cmd-n`, or `ctrl-n` away from macOS) starts a fresh one from anywhere. Home reopens the last conversation when the app starts.
- **Workspaces** create a workspace and record its intake: project type, package manager, runtime, safe commands, ignored paths, safety mode and whether mobile may supervise it. **Detect project** reads the workspace directory names and fills the profile in, suggesting safe commands and ignored paths for that ecosystem.
- **Inbox** captures tasks, with the prompt they carry, their state in its own ink, and where they came from; **Start session** on one runs it and opens the run as a conversation in Home, and a task that already ran shows **Open run** instead of starting again. **Sessions** lists every run, streams its logs, and offers **Open in Home** so any run can be read as a conversation. Starting a session is an explicit action, and a guarded workspace refuses a command that is not in its safe commands.
- **Reviews** list the files a run changed (one path per line), approve or reject them with a reason, record follow-up conditions, and open the run behind them.
- **Readiness** scores whether this workspace can run agents: the score is coloured by its verdict — not ready, almost ready, ready to run — and every blocker is listed, with what is not required yet kept apart. **Weekly review** summarizes progress over time from stored activity: what shipped, what is blocked, what was rejected, risky patterns and next actions, each list in its own colour. **Generate review** saves a new one, and says so when it cannot.
- **Pairing** shows a QR code for the mobile app, and the `kloucy://pair?token=…` link the code carries: **Copy link** sends it to the clipboard, so a phone that cannot scan can still open it. The state of the code (pending, claimed, revoked) is coloured.
- **Settings** correct workspace data, set the default agent, and archive a workspace.

## Command palette

Press `cmd-k`, or `ctrl-k` away from macOS, to open the palette from anywhere in the app. Type to filter, then pick a command:

- jump to any section, chats included
- start a new workspace
- create a new pairing code

Press the shortcut again, press escape, or click outside the palette to close it.
